# 来源选择、渠道分级与访问策略

渠道是否“官方”不是唯一判断标准。文献发现重视覆盖度，身份核验重视可追溯性，结论提取重视原文层级。第三方渠道可以而且应该使用，但要按其证据能力承担合适角色。

## 四种来源角色

| 角色 | 能做什么 | 不能单独证明什么 |
|---|---|---|
| 发现源 | 用主题、引文、作者、相似度或全文索引找到候选 | 候选一定存在、题录完全正确、研究结论成立 |
| 身份核验源 | 核对题名、作者、年份、期刊、DOI/稳定ID之间的对应关系 | 论文一定与用户问题高度相关 |
| 内容证据源 | 用摘要或全文支持相关性、方法、结果与数值 | 期刊分区、引用数等外部属性 |
| 属性核验源 | 核验分区、收录、撤稿、更正、OA状态、引用数等 | 论文主题与实验结论 |

同一渠道可承担多个角色，但报告中要分开写。出版社单篇页能核验一篇论文，不能因此声称“检索了该出版社数据库”。

## 渠道分级

### A. 注册机构、出版社与学科数据库

可用于直接身份核验，也可在实际执行站内查询时作为发现源。

- DOI/元数据注册：Crossref、DataCite
- 出版社与期刊平台：ACS、RSC、Wiley、ScienceDirect、Springer Nature、Taylor & Francis 等
- 学科数据库：PubMed、Europe PMC、ERIC、IEEE Xplore 等，按主题选择
- 预印本平台：ChemRxiv、arXiv、bioRxiv 等；必须标记为预印本
- 中文学术数据库：CNKI、万方、维普等；在实际进入结果页查询时算发现源

注意：DOI 字符串格式合法不等于记录真实。必须打开 DOI 注册记录、出版社页或其他可追溯记录，确认 DOI 与题名对应。

### B. 第三方结构化学术索引与聚合平台

它们是正常且重要的发现渠道，不因“第三方”而降格为不可用：

- OpenAlex：跨学科检索、作者/机构、引用关系、OA位置
- Semantic Scholar：主题检索、参考/被引、相似论文与推荐
- Lens：结构化学术检索、引文关系及专利—论文连接；按实际权限使用
- Dimensions、Scopus、Web of Science、Engineering Village：有合法权限时使用
- CORE、BASE：开放仓储和全文发现
- Google Scholar：广覆盖发现、被引线索与作者版本定位
- Crossref Metadata Search：可参与候选发现，但其强项仍是 DOI 元数据

结构化第三方索引可参与身份核验。若注册记录、出版社页或学科数据库均不可访问，至少用两个不同平台的结构化记录交叉核对题名、作者/作者组、年份和稳定ID，并披露这些平台可能共享上游元数据，不能把“两个页面”夸大成完全独立的原始证据。

### C. 引文地图与推荐工具

- ResearchRabbit
- Connected Papers
- Litmaps
- Inciteful
- Semantic Scholar Recommendations

适合种子扩展、发现相邻术语与漏检论文。推荐关系是“候选生成”，不是存在性或相关性证明。每篇候选仍需经过身份门槛。

### D. 通用网页与非学术第三方线索

- 通用搜索引擎与网页搜索 API
- ResearchGate、Academia.edu、ORCID/作者主页、机构课题组网页
- 学术新闻、博客、媒体、论坛、社交平台、参考文献列表的未解析文本

这些渠道可以发现非常新、非常偏或元数据尚未充分入库的论文，但单个搜索摘要、博客条目、AI摘要或社交帖子只能作为线索。不得仅凭它们输出“已确认文献”，也不得从其片段补作者、DOI或性能数值。

## 公开结构化来源速查

| 来源 | 主要角色 | 注意事项 |
|---|---|---|
| OpenAlex | 发现、身份交叉核验、引用关系 | 摘要可能缺失或为倒排结构；主题标签可能是算法生成 |
| Crossref | DOI身份核验、出版元数据；可辅助发现 | 以成员提交元数据为主，字段可能缺失；不能只靠模糊首条结果认领 DOI |
| DataCite | 数据集、预印本及部分出版物标识核验 | 与 Crossref 覆盖侧重不同 |
| Semantic Scholar | 发现、引用/参考、推荐、身份交叉核验 | 无 Key 时易429；TLDR/推荐为算法产物，不当作原文结论 |
| ChemRxiv | 化学/化工预印本发现与版本核验 | 未经同行评审，检查是否已有正式版 |
| CORE / BASE | 开放仓储与全文发现 | 同一论文可能多仓储重复；元数据质量不均 |
| Unpaywall | 按 DOI 定位合法 OA 版本 | 不是主题发现引擎；通常需要联系邮箱 |
| PubMed / Europe PMC | 生物化工、毒理、环境健康、生物材料 | 不适合作为所有化工主题的默认来源 |
| arXiv | 过程建模、控制、计算、机器学习 | 工艺实验类覆盖有限；检查正式发表版本 |
| Lens | 发现、引文网络、专利连接 | API/高级功能可能需要账户或权限 |

## 每篇文献的最小证据链

正式列为“已确认”的记录必须同时满足：

1. **发现证据**：本轮某个结果页、API响应、引文图谱或网页线索中实际出现过该候选；
2. **稳定身份**：DOI 或 PMID、PMCID、arXiv ID、数据库稳定记录 ID 之一；确无标识符的老文献需有可追溯期刊/仓储记录；
3. **身份核验**，二选一：
   - 一个直接核验源：注册机构、出版社、学科数据库或可信机构仓储，且题名与稳定ID相互对应；
   - 两个不同的结构化学术索引，核心题录一致；
4. **相关性依据**：明确写 `题名`、`摘要` 或 `全文`；
5. **访问记录**：保存渠道名、角色、记录链接/端点和访问日期。

只有通用搜索摘要或第三方文章提及、无法通过身份门槛的候选，放入“待核验线索”，不得混进正式清单。

## 发现来源的独立性与计数

“来源”按实际发现入口计数：独立 API、数据库结果页、开放仓储结果页、引文图谱查询或获批浏览器完成的站内查询可算发现来源。

以下情况不能凑成多个独立发现源：

- 同一通用搜索引擎的多组关键词或多个 `site:` 查询；
- DOI解析页与其跳转后的出版社单篇页；
- 同一平台的 API 和网页界面返回同一结果集；
- 出版社单篇落地页；
- 多个转述同一新闻稿的博客页面。

多个聚合平台可能共享 Crossref 等上游数据。它们仍可作为不同检索入口，但在“证据独立性”上要诚实说明共享上游风险。

## 模式到来源

### 快速检索

优先组合一个广覆盖结构化索引与一个互补入口，再做记录级核验：

- 通用化工：OpenAlex + Semantic Scholar/Lens；Crossref或出版社核验
- 染料合成/光物理：OpenAlex + Semantic Scholar + ChemRxiv；注册记录/出版社核验
- 染料废水：OpenAlex + Semantic Scholar；必要时 PubMed/Europe PMC
- 相变材料：OpenAlex + Semantic Scholar/Lens；仓储或出版社补最新
- 中文工程应用：国际来源 + CNKI/万方/维普中的一个实际检索
- 工具受限时：网页搜索 + 一个结构化学术索引；逐篇使用注册记录、出版社或第二索引核验

### 系统或结构化检索

至少选择：

1. 一个广覆盖发现源；
2. 一个互补学术索引或学科数据库；
3. 一个 DOI/出版元数据核验源；
4. 主题需要时增加中文、预印本、开放仓储或生物医学源。

报告必须列出未访问的关键数据库，不能把公开来源覆盖说成绝对穷尽。只有形成可追溯结果集、筛选数字和去重过程时才使用“系统检索”字样。

## 登录型与权限型渠道

SciFinder-n、Reaxys、Web of Science、Scopus、Engineering Village、Dimensions高级功能以及部分中文数据库，只在用户已有合法权限和批准的登录会话时使用。不得索要或保存账号密码，不得将“未检索”写成“无结果”。

## 故障切换

- 429：遵守 Retry-After；降低请求量或换来源，不连续轰炸。
- 空结果：检查字段、编码、年份和同义词，再换来源；不要立即断言没有研究。
- 页面反爬/验证码：改用公开 API，或请用户正常完成验证。
- Exa或某后端未注册：记录失败，切换可用网页搜索或结构化学术源，不伪称访问成功。
- 元数据冲突：不要静默挑一个值；优先直接核验源并保留冲突说明。
- DOI解析成功但题名不符：视为身份冲突，不能纳入。
- 全文不可得：查 Unpaywall、CORE、机构仓储或作者公开版本；仍不可得则标记机构权限需求。
